# The prompts behind this site

These are the prompts I used to build SLOP4761. They are *engineered* prompts,
not chat transcripts: each one was written deliberately before a build pass —
stating the outcome, the constraints, what to preserve, what to supersede and
what to verify — rather than typed a line at a time while the work happened.
That is why they read like specifications. Writing them this way is the part of
the process I was actually practising.

They are reproduced as written, with one editorial change: absolute paths to
this repository on my machine are replaced with "this repository".

| Prompt | What it directed |
|---|---|
| [`01-first-draft.md`](01-first-draft.md) | The first complete draft, built from the research already in `research/`, preserving the fixed platform |
| [`02-consultancy-redesign.md`](02-consultancy-redesign.md) | The redesign into a consultancy case: five fixed homes, a measurement programme, then an investment proposal |
| [`03-fast-weekly-coherence.md`](03-fast-weekly-coherence.md) | The narrow coherence pass — one weekly map over the teaching content that already existed, deliberately scoped against further expansion |
| [`04-teaching-materials-and-guided-navigation.md`](04-teaching-materials-and-guided-navigation.md) | Assessments, twelve tutorials, twelve decks, grouped navigation, walkthroughs and the planner |
| [`05-finish-interrupted-pass.md`](05-finish-interrupted-pass.md) | Finishing the design-contract alignment left interrupted by the previous pass |
| [`06-codex-visual-finish-and-audit.md`](06-codex-visual-finish-and-audit.md) | Integrating the supplied artwork and auditing the near-final site |

Not every instruction came from a prepared prompt. The last round of visual
fixes came from me opening the site in a browser and reporting what I saw, and
those are quoted where they matter in [`../../PROCESS.md`](../../PROCESS.md).

`research/course-design.md` is the design contract these prompts kept changing;
`CLAUDE.md` is the harness that holds the result to it.
